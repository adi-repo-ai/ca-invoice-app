2. Data, backup and continuity

2.1 Restore tool Next Free

Today, Settings → Backup downloads a JSON file, but there is no way to load it back. The restore tool closes that gap and is the key to recovering from losing a Firebase project.

  • Who: owners only (ADMIN with Revenue permission). Runs through a Netlify function using the Admin SDK, or as a command-line script for a brand-new project.
  • Step 1, check: upload the backup file; the tool validates it (format version, firm settings, counters, clients, invoices, users) and shows a dry-run summary: "412 clients, 3,180 invoices, 4 users will be restored".
  • Step 2, choose: Restore into an empty project (disaster recovery) or Restore only missing records (never overwrites existing data).
  • Step 3, restore: writes in batches of 500, keeping the original IDs, invoice numbers and financial-year counters so numbering continues correctly. Progress bar; safe to resume if interrupted.
  • Users: user records are recreated as invites; staff sign in again with Google or set a new password. Roles and permissions are restored.
  • Audit: a RESTORE entry is written to the activity log.
  • Free-plan note: the free plan allows 20,000 writes a day. Restores larger than that continue automatically the next day.

2.2 Automatic weekly backup by email Next Free

  • A Netlify scheduled function runs every Sunday night (IST), reads all data with the Admin SDK and builds the same backup file as Settings → Backup, compressed (.json.gz).
  • Emails it to two owner addresses through a free email service (e.g. Brevo, 300 emails/day free). The SMTP key lives only in Netlify environment variables.
  • Owners choose the addresses and can turn it off in Settings → Backup; the page shows "Last automatic backup: Sunday 28 Sep, 11:00 pm ✓".
  • Cost: one read per record per week (e.g. 4,000 reads, well within 50,000/day).
  • If the file ever grows too large for an email attachment, it switches to a private Google Drive folder instead.

2.4 Account continuity checklist (owner actions, no code)

  • Add a second Owner to the Firebase project (Project settings → Users and permissions).
  • Google account: recovery phone and email, 2-Step Verification, printed backup codes in the office safe.
  • Netlify and GitHub: second team member / collaborator, 2FA on, recovery codes saved.
  • Offline "break-glass" pack: latest backup, Netlify environment variable values, a code ZIP, backup codes.
  • Remove SETUP_CODE from Netlify after setup; rotate the Firebase admin key yearly.

3. Recurring invoices Next Free

  • Mark a client service as recurring: monthly accounting, quarterly GST filing, yearly audit/ITR.
  • Each template holds client, service lines, amount, frequency, day of month and an end date (optional).
  • On the due day the portal creates a draft (never issues automatically) and shows it in the notification bell and on Home: "4 recurring drafts ready to review".
  • One click to review and issue; the period is filled in, e.g. "Accounting services – October 2026".
  • Runs on a free Netlify scheduled function, or when an admin opens the portal.

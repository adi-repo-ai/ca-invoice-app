1. Access levels: who can do what

Every person has a role (ADMIN or STAFF) and two permissions that an owner switches on or off in Settings → Users:

  • Revenue & reports: revenue totals on Home, the Reports page, CSV export, monthly goal and Backup. ADMINs only.
  • Payments, receipts & statements: record payments, see payment details, receipts and client statements.

How it is enforced: recording payments, deleting and changing access are checked by the database rules and server functions, not just hidden in the browser. Revenue totals are hidden from the screens. Admin B and Staff can still see each invoice's own amount (needed to create and send invoices), so this keeps totals need-to-know rather than secret.

1.1 Setting up the three levels

  1. Admin A (owner). The first admin (set up with the setup code) is an owner. Accounts that were admins before this update are owners automatically. Owners show the badge "Owner · full access" in Settings → Users.
  2. Admin B. Settings → Users → Add a user → enter their Google email, choose the access level Admin · no revenue, no payments → Add user. They get it at first sign-in; nothing else to do.
  3. Staff. Same, but choose Staff · with payments (payments, receipts and statements on).
  4. Adjusting. As an owner, use the two switches under each person in Settings → Users. They are signed out and get the new access when they sign in again. Turning on "Revenue & reports" makes that admin an owner, so only do it for people who should see everything.
Check after updating: if you added a second admin before this update, they are also an owner now. Open Settings → Users and switch off "Revenue & reports" and "Payments, receipts & statements" for them to make them Admin B. Keep at least two owners if possible (or one owner plus a safe way back: section 4). Only owners can add, change or remove users; Admin B sees the Users list read-only.

2. Managing users inside the portal (recommended)

Everything is in Settings → Users (visible to ADMINs; only owners can add, change or remove users). The portal method is preferred because it cleans up everything in one click.

2.1 Add a user

  1. Under Add a user, type the person's Google email (Gmail or Google Workspace address).
  2. Choose the Access level and click Add user. Owners can pick any of: Owner · full access, Admin · no revenue, Admin · no revenue, no payments, Staff · with payments, Staff · no payments. Admins who are not owners can only pick Admin · no revenue, no payments or Staff · with payments.
  3. They appear under Waiting to sign in.
  4. Send them the site link. They click Sign in with Google using that same email, and they are let in automatically.
  5. They then move to People with access, which shows "Active now" or when they were last active.

To cancel an invite before it is used, click Remove next to the email under Waiting to sign in.

2.2 Change someone's role

  1. Find the person under People with access.
  2. Click Make ADMIN or Make STAFF and confirm. A role change never gives revenue access; an owner switches that on separately.
  3. They are signed out and get the new role when they sign in again.

2.3 Block someone temporarily

For leave, a lost phone or a suspected misuse:

  1. Click Disable on their row and confirm. They are signed out at once and cannot sign in.
  2. To restore access, click Enable. Nothing is lost.

2.4 Delete someone permanently

For example, when a person leaves the firm:

  1. Click Delete on their row.
  2. Type DELETE in the box and click Delete user.

This removes:

  • their sign-in account and access
  • any pending invite
  • their private tasks, events, notes and links

Invoices and clients they created are kept. To give them access again later, add their email again as in 2.1.

3. Managing users in the Firebase console (backup method)

Use this only if the portal is not available, or to double-check. Open https://console.firebase.google.com and select the project ca-invoice-app.

3.1 Find a user

  1. In the left menu, open Build → Authentication → Users.
  2. Each row shows:
    • the email
    • the sign-in method (Google or email)
    • the User UID, a long code you will need below

3.2 Disable a user (temporary)

  1. Click ⋮ at the end of the user's row, then Disable account.
  2. To undo, use Enable account from the same menu.
  3. Also click Disable in the portal, so the Users page shows the correct status.

3.3 Delete a user completely: do all four steps

  1. Authentication → Users:
    • Note the person's User UID.
    • Click ⋮, then Delete account, and confirm. They can no longer sign in.
  2. Build → Firestore Database → Data:
    • Open the users collection and find the document whose name equals that UID.
    • Use the ⋮ menu at the top of the document to choose Delete document.
    • Without this step, they still appear on the portal's Users page.
  3. In the invites collection, if a document named with their email exists, delete it. Otherwise they could sign in again and regain access.
  4. Optional: in the tasks, events, notes and links collections, delete documents whose ownerUid equals that UID.

3.4 What the console cannot do

  • Change roles. ADMIN / STAFF is stored in a protected place the console does not show. Change roles only in the portal (2.2).
  • Give access by itself. If someone signs in with Google without being on the Users list, Firebase creates a sign-in account for them. They only see "No access yet", and these stray accounts are safe to delete in Authentication.
Never delete these Firestore collections or documents in the console:
  • counters: invoice numbering
  • settings: firm details
  • system: setup lock
  • auditLog: invoice history
Delete invoices only in the portal (Invoices page), so the history log records it.

4. If all admin access is lost

  1. In Netlify, open Site configuration → Environment variables:
    • Add SETUP_CODE with a new secret of 12 or more characters.
    • Go to Deploys → Trigger deploy → Deploy site.
  2. In the Firebase console, open Firestore Database → Data → system and delete the document bootstrap.
  3. Sign in to the portal with Google. On the "No access yet" screen, enter the setup code. You become ADMIN.
  4. Delete SETUP_CODE from Netlify again and redeploy.
Step 3 works only when no admin exists at all. If an admin account still exists but nobody can use it, first delete that account as described in 3.3. Keeping two admins avoids this situation entirely.

5. Good practice checklist

  • Delete SETUP_CODE from Netlify once the first admin is set up, then redeploy.
  • Keep two ADMIN accounts.
  • Delete users who leave the firm on their last day (2.4). Use Disable for temporary blocks.
  • Once a month, take a backup in Settings → Backup and keep the file safe (Google Drive or a USB drive). The free Firebase plan has no automatic backups.
  • Sign out on shared computers. The portal also signs you out automatically after 30 minutes of inactivity.
  • Share only invoice PDFs with clients, never the portal link or your login.

6. Limits for clients and invoices

The portal has no fixed limit on how many clients or invoices it stores. The practical limits come from the invoice number format and Firebase's free (Spark) plan.

LimitValueWhat it means
Invoices per financial year9,999Numbers have 4 digits (LKA/2026-27/0001 to 9999) and restart every 1 April. That is about 27 invoices a day, every day.
ClientsNo app limitTens of thousands would still fit.
Service lines per invoice50Plus up to 30 reimbursement lines.
Services in the Settings list100Each with an optional default price.
Total storage (free plan)1 GBOne invoice with its history is about 5 KB, so roughly 150,000–200,000 invoices in total: decades of use for a small firm.
Reads per day (free plan)50,000Opening the invoice list uses about 25 reads; a busy day uses a few hundred to a couple of thousand.
Writes per day (free plan)20,000Creating and issuing an invoice uses about 4–6 writes.
Deletes per day (free plan)20,000Matters only for very large "Delete all" actions.
If a daily limit is reached:
  • The portal shows an error until the limit resets, at about 1:30 pm IST each day.
  • There are never any charges. The free plan simply pauses; it does not bill you, and no card is needed.
  • With normal use you will not come close. Only very large one-off jobs could reach a limit, such as a backup or CSV export of thousands of invoices.
  • You can check usage in the Firebase console under Firestore Database → Usage.

7. Trying access levels on the test site

Use the test site (staging--lingeshwarca-invoice.netlify.app, yellow "TEST SITE" banner) to try changes and access levels without touching real data:

  • Owner: make yourself owner of the test project with its setup code (or npm run create-admin -- --key …).
  • Sample data: Settings → Test site: sample data → Load sample data adds 6 made-up clients (marked TEST) and 10 invoices. Only owners see it, and only on test addresses.
  • Admin B and Staff logins: add two of your other Gmail addresses under Settings → Users with those access levels, or run npm run seed:test -- --key … --password … to create adminb.test@example.com and staff.test@example.com (sign in with email & password).
  • Never put real client data on the test site. Setup steps for both sites: docs/LKA-Invoices-Environment-Setup.pdf.

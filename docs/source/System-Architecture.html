1. What the portal does

A private web app for the firm's staff to keep client records, create GST-compliant invoices, and send them to clients as PDFs by email or WhatsApp. It runs in any modern browser on a phone or computer; there is nothing to install.

Who uses itOnly people added by an ADMIN in Settings → Users (currently two people). Clients never log in; they only receive PDF invoices.
Main jobsClient list · invoice drafts · issue with automatic numbering (LKA/2026-27/0001) · PDF with UPI QR · email / WhatsApp sharing · payment reminders · receipts · client statements · reports · dashboard with alerts · CSV import/export · activity log · backup.

2. Architecture at a glance

The portal has no traditional server of its own. The website runs in the browser and talks directly to Google Firebase for sign-in and data. A few admin-only jobs go through small Netlify server functions that hold the secret admin key.

Figure 1: System context. Solid arrows carry data over HTTPS with the user's sign-in token. The PDF goes from the device straight to the client.

4. How it works: key flows

4.1 Signing in and getting access

Figure 2: First sign-in of an invited person. The role is stored inside the signed token, so it cannot be faked by the browser.

4.2 Creating and issuing an invoice (direct to Firestore)

Figure 3: Issuing an invoice. Numbers are gap-free and never duplicated because the counter and invoice are written together.

4.3 PDF, email and WhatsApp

  1. View / Download PDF: the browser loads the invoice, draws the A4 PDF with your logo, signature (if switched on) and a UPI QR code (unpaid invoices only). It opens in a tab or downloads. Nothing is uploaded.
  2. Send by email / WhatsApp: on phones the share sheet opens with the PDF attached. On computers the PDF downloads and a ready-written Gmail / mail or WhatsApp chat opens for you to attach it.
  3. A "sent by email / WhatsApp" entry is written to the invoice's history log.
  4. Payment reminders (issued invoices): one click opens WhatsApp or email with a polite reminder showing amount, days overdue and UPI ID. Text only, no attachment.
  5. Receipts (paid invoices): a "RECEIPT" PDF with amount received, TDS and mode; download or send it the same way.
  6. Client statements: on a client's page, a "STATEMENT" PDF for any period listing every invoice and payment with a running balance.
  7. All message wording comes from editable templates in Settings → Goals & messages. All PDFs (invoice, receipt, statement) are made in the browser and never uploaded.

4.5 Dashboard, alerts and reports (read-only views)

  • Home: today's overdue / to-collect / tasks / events tiles, nudges (old drafts, very late invoices), 6-month chart, monthly goal ring, weekly summary, recent activity, milestones and a getting-started checklist. Uses cheap server-side sums and counts (about 30 reads per visit).
  • Notification bell: overdue invoices, tasks due, today's events, stale drafts; refreshes every 5 minutes.
  • Reports (all staff): per financial year, billed vs received by month, collection rate, outstanding by age, top clients and who owes you; CSV export. Reads each invoice of the chosen year once.
  • Search (Ctrl+K): clients by name, invoices by number (e.g. "12"), and pages. Activity log (ADMIN): every create / issue / payment / send / cancel / delete, newest first.

4.4 Admin jobs (through Netlify Functions)

Used for: changing roles and access (owners only), disabling / enabling / deleting users (owners only), first-admin setup, restarting numbering.

  1. The browser sends POST /.netlify/functions/<name> with a small JSON body (e.g. {"action":"delete","uid":"…"}) and the header Authorization: Bearer <ID token>.
  2. The function verifies the token with Google, checks the caller is ADMIN, validates the input (e.g. "cannot delete yourself").
  3. It acts with the Admin SDK using the secret service-account key kept only in Netlify's environment variables.
  4. Replies {"ok":true} or {"error":"…"}, shown as a message in the portal.

5. Data: what is stored and how

Firestore stores documents (like small records) grouped in collections. Each invoice keeps its own frozen copy of the client and firm details, so later edits to a client or settings never change an already-issued invoice.

CollectionWhat one document holdsWho can read / write
settings/firmFirm name, address, GSTIN/PAN, bank & UPI, logo, signature, GST switch & rate, services list, prefix, terms, monthly goal, message templatesAll staff read · ADMIN writes
clientsName, contact person, address, state, GSTIN, PAN, email, mobile / WhatsApp, tags (e.g. ITR, GST), internal notes (never printed)All staff read, add, edit, delete
invoicesStatus, number, dates, client snapshot, firm snapshot, items, reimbursements, totals (paise), amount in words, notes, terms, payment detailsAll staff; issued invoices locked; numbered ones deletable by ADMIN only
counters/{FY}Last invoice number used in that financial year (e.g. 2026-27 → 12)Only moves +1 together with an invoice; reset via function
auditLogWho did what to which invoice and when: create, edit, issue, payment, cancel, delete, sentStaff add only; never edited or deleted
usersEmail, name, role, revenue & payments permissions, disabled flag, last seen timeOwners manage (via functions); other admins view only; user updates own "last seen"
invitesEmails allowed to join, with the access level they will getOwners add / remove; admins can view
tasks, events, notes, linksPersonal Home-page itemsOwner only, private even from admins
system/bootstrapOne-time lock for the first-admin setupServer only
Data format details: money is always an integer number of paise (no decimal rounding errors); dates are YYYY-MM-DD in Indian time; financial year runs April–March; invoice numbers look like LKA/2026-27/0001. In transit, the Firebase SDK sends data as encrypted HTTPS (binary protocol); Netlify Functions use JSON over HTTPS.

7. Security

Figure 5: Defence in depth. Even someone who bypasses the website cannot get past layers 2–4.

ThreatHow the portal handles it
Stranger finds the URLSees only the sign-in page; not on the allow list → "No access yet", zero data readable.
Someone edits browser codeUseless: all checks are enforced by Google's servers (rules) and the functions, not by the browser.
Tampering with an issued invoiceRules forbid editing issued invoices; only status changes (payment / cancel) are allowed, and each is logged.
Duplicate or skipped numbersCounter and invoice saved together in one transaction; rules require number = last + 1.
Staff over-reachSTAFF cannot change settings or users, cancel, or delete invoices or clients (enforced by the rules).
Revenue / payment need-to-knowTwo per-person permissions in the sign-in token: revenue (totals, Reports, CSV export, Backup) and payments (record payments, receipts, statements). Recording a payment is refused by the rules without it; only an owner (admin with revenue) can change permissions, and other admins cannot change or remove an owner. Individual invoice amounts stay visible to everyone who invoices.
Leaked Firebase web configNormal and safe: it only identifies the project; access still needs sign-in + rules.
Lost / shared device30-minute idle sign-out; ADMIN can Disable the account instantly (signs out everywhere).
Admin key exposureStored only in Netlify environment variables; never committed to GitHub; never sent to browsers.

8. Privacy

What is storedBusiness records only: firm details, client contact & tax IDs, invoices, payments, staff emails/roles, personal Home notes. No passwords are stored by the app (Google handles sign-in).
What is NOT stored or sentInvoice PDFs (made on the device) · no analytics, tracking or ads · no third-party data sharing · no card/bank login details.
Who sees whatSigned-in firm users see all invoices & clients (shared work). Each person's tasks, events, notes, links are private to them, even from admins.
Where it livesYour own Firebase project on Google Cloud, in the region chosen when the database was created (Firebase console → Firestore → Settings). Encrypted in transit and at rest by Google.
Your responsibilities: PDFs downloaded or shared by email / WhatsApp are copies outside the portal. Treat them like any client document. Sign out on shared computers. Remove leavers promptly. Use the backup file carefully: it contains all business data.

11.2 How to make a change safely

  1. Edit code in a copy of the GitHub repo (or ask a developer / AI assistant). Most visual changes: src/pages/*; PDF layout: src/pdf/InvoicePdf.tsx; GST maths: src/lib/tax.ts; permissions: firestore.rules.
  2. Run checks: npx tsc -b (types), npm run test:all (93 tests incl. security), npm run build.
  3. Try it locally with emulators (npm run seed:emulator, demo data, no real data touched).
  4. Push to staging → test on the test site (deploy changed rules with --project ca-invoice-app-staging). When approved, merge staging into main → Netlify deploys live; deploy changed rules with --project ca-invoice-app (section 9).
  5. To undo a bad release: Netlify → Deploys → pick the previous deploy → Publish deploy (instant rollback).

11.3 Restoring data

The backup is a JSON file of settings, clients, invoices, counters and audit log. There is no one-click restore screen; restoring is done by a developer with a small script using the Admin key. Keep backups in a safe, private location.

11.4 Possible future enhancements

  • Custom domain (e.g. invoices.yourfirm.in): about ₹800–1,200/year for the domain; Netlify provides HTTPS free.
  • Automatic email sending from the portal and login alerts (need an email service such as Brevo free tier + a Netlify function).
  • Recurring invoices for retainer clients; mobile app experience (installable app, bottom navigation, swipe actions).
  • One-click restore from backup; scheduled automatic backups; Excel export for Tally.
  • Client portal, online payments (Razorpay / Cashfree), multi-branch, e-invoicing (IRN) if GST turnover requires it.

The full prioritised list, with effort and cost for each item, is in docs/LKA-Invoices-Future-Enhancements.pdf (Word copy alongside).

11.5 Where roles live

Roles and the two permissions are stored in Firebase (on each person's sign-in account, with a copy in users) and enforced by the Firebase security rules on every read and write. They are changed only by the Netlify functions, because changing them needs the Firebase admin key, which lives only in Netlify's environment variables. The browser can ask, but can never set a role itself.

11.6 If you lose access to Google, Firebase or Netlify

LostWhat to do
Google accountGoogle account recovery (recovery phone / email, printed backup codes). If a second Owner was added to the Firebase project, sign in with that account and carry on.
NetlifyData is safe in Firebase. New Netlify account → Import from GitHub → paste the environment variables (or create a new Firebase service-account key) → deploy → add the new site address under Firebase Authentication → Authorized domains.
Firebase, no second ownerNew Firebase project (Spark) → deploy rules and indexes → restore the latest backup file (needs the planned restore tool) → update Netlify variables → recreate the first admin with SETUP_CODE. Anything after the last backup is lost.
Portal admin loginSet SETUP_CODE in Netlify, delete system/bootstrap in the Firestore console, claim admin on the site, then remove SETUP_CODE. Or run scripts/create-admin.ts.
GitHubThe site keeps running. Upload a code copy to a new repository and reconnect Netlify.
Prevent it: second Firebase Owner; second Netlify and GitHub member; 2-step verification everywhere; monthly backups; an offline pack with the latest backup, Netlify variable values, a code ZIP and backup codes.

12. Troubleshooting

SymptomLikely cause → fix
"You do not have permission… or data failed validation"Rules on Firebase are older than the code → Cloud Shell: git pull then deploy rules. Or the action needs ADMIN.
"The query requires an index"Indexes not deployed → deploy firestore:indexes from Cloud Shell; wait a few minutes.
"No access yet" after Google sign-inEmail not in Settings → Users, or typed differently → add exactly that Google email.
Admin actions fail with server / token errorNetlify env vars missing or wrong (FIREBASE_*) → fix in Netlify, redeploy.
Site shows old versionHard refresh (Ctrl+Shift+R); check Netlify Deploys finished.
Errors late in the day, then fine next dayFree daily quota reached (rare) → wait for reset (~1:30 pm IST).
QR code missing on PDFNo UPI ID in Settings, or invoice already paid / cancelled (by design).
